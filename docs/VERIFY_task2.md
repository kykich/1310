# Как проверить задачу 2 (AI-ревью PR)

Задача 2 из `docs/Final_task.md`: пайплайн анализирует новый PR — получает
diff и изменённые файлы, использует RAG (документация + код) и выдаёт ревью
с потенциальными багами, архитектурными проблемами и рекомендациями.

Ниже — проверки от самой дешёвой к полной. Все команды выполняются из корня
проекта **`G:\9potok\1310`** (там лежат `review_pr.py` и `rtk_app/pr_review.py`).
Проверяемый репозиторий может быть любым — например, `G:\9potok\test1310\1210`.

## 1. Автономные тесты (без сети, ключей и Ollama)

```powershell
cd G:\9potok\1310
python -m tests.check_pr_review
```

Ожидаемо: `Итог: 86 OK, 0 FAIL`. Проверяются: сбор diff/файлов на временном
git-репозитории, лимит diff, пустой диапазон ревизий, RAG-запрос, промпт с
тремя разделами, полный цикл с фейковой моделью, деградация без RAG, локальная
модель (включая reasoning-модели), автоопределение локального сервера и
команда `/review` в чате (§9).

## 2. CLI на реальном PR-диффе (без RAG)

```powershell
cd G:\9potok\1310
python review_pr.py --repo G:\9potok\test1310\1210 `
  --base HEAD~1 --head HEAD --no-rag --model DeepSeek-flash `
  --out review1210.md
```

Что проверить в `review1210.md`:

- шапку: `## AI-ревью PR`, `модель: DeepSeek-flash`, число изменённых файлов,
  `RAG: не использован (отключён)`;
- три раздела: `## Потенциальные баги`, `## Архитектурные проблемы`,
  `## Рекомендации`;
- ссылки на файлы/строки из diff и уровни `[critical|high|medium|low]`.

Для больших диффов добавьте `--max-tokens 8000`, иначе ответ может обрезаться.

## 3. CLI с RAG (документация + код)

```powershell
python review_pr.py --repo G:\9potok\test1310\1210 `
  --base HEAD~1 --head HEAD --build-index --model DeepSeek-flash `
  --max-tokens 6000 --out review1210_rag.md
```

`--build-index` индексирует папку репозитория (README, `docs/`, код, PDF).
В шапке должно быть `RAG: использован`, а в тексте — ссылки на документы/код
проекта, а не только на diff. Нужна запущенная Ollama с моделью
`nomic-embed-text-v2-moe` (проверка: `ollama list`).

Примечание: индекс общий (`session/rag_index.db`), но поиск ограничен
`docs_dir` проверяемого репозитория — чанки других проектов в ревью не
попадают.

## 4. Локальная модель

```powershell
# 1) запустить модель в блоке «Локальная модель» UI (порт 8080)
# 2) затем:
python review_pr.py --repo G:\9potok\test1310\1210 `
  --base HEAD~1 --head HEAD --no-rag --model Local --out review_local.md
```

URL можно не указывать: CLI читает `session/local_model.json` и проверяет
`/v1/models`. При `--model Local` без запущенного сервера будет понятная
ошибка (без подмены на GigaChat). Явный вариант:
`--local-url http://127.0.0.1:8080/v1 --local-model Local`.

Reasoning-модели (например, Qwen3.5) по умолчанию тратят весь `max_tokens`
на `reasoning_content`, оставляя `content` пустым. Для ревью thinking
отключается (`chat_template_kwargs.enable_thinking=false`); обычный чат при
пустом `content` делает повторный запрос автоматически.

Для Local diff автоматически ограничивается под контекст модели
(`local_review_diff_limit`, ctx из `session/local_model.json`), иначе
llama-server с ctx 8192 отвечает HTTP 400 на большой diff. В шапке ревью
появляется «diff обрезан по лимиту».

## 5. GitHub Action (реальный PR)

1. Убедиться, что в репозитории есть `.github/workflows/ai-review.yml`
   (в нашем проекте он уже добавлен).
2. Settings → Secrets and variables → Actions: добавить `DEEPSEEK_API_KEY`
   (или `GIGACHAT_KEY`).
3. Создать ветку, изменить код, открыть Pull Request.
4. Workflow `AI PR review` запустится на `opened/synchronize/reopened`,
   выполнит `review_pr.py` и **добавит комментарий** в PR (плюс артефакт
   `ai-review`).

Если Ollama в CI недоступна (шаг `continue-on-error`), ревью всё равно
выполнится — без RAG, с пометкой причины в шапке.

## 6. Через чат (команда `/review`)

Запустите сервер (`python rtk_web.py 8123`), в поле `docs:` укажите
репозиторий (например, `G:\9potok\test1310\1210`) и отправьте в чат:

```
/review                    # последний коммит (HEAD~1..HEAD)
/review origin/master HEAD # конкретные ревизии
/review --no-rag           # без RAG (быстрее/дешевле)
```

Модель — выбранная в селекторе, модель персоны или запущенная локальная.
Если модель не выбрана и локальная не запущена, `/review` ответит подсказкой.
Результат — Markdown-ревью с тремя разделами в карточке чата.

Если `base` и `head` указывают на один коммит (например, `/review origin/master`,
когда `origin/master == HEAD`), ревью не выполняется: возвращается ошибка
«Нет изменений между …» с названием общего коммита и подсказкой
`/review HEAD~1 HEAD`. Это защищает от пустого ревью и лишних запросов к модели.

## 7. Что считать успехом

- `check_pr_review` — 0 FAIL;
- в `review*.md` есть все три раздела и ссылки на файлы/строки diff;
- с `--build-index` в шапке `RAG: использован` и в тексте упомянуты
  документы/код проекта;
- с запущенной локальной моделью `--model Local` работает без `--local-url`;
- в PR появляется комментарий от workflow.

## Типовые проблемы

| Симптом | Причина / решение |
|---|---|
| `Не выбрана ни одна модель` | запустите локальную модель или укажите `--model DeepSeek-flash/GigaChat` |
| `модель недоступна (локальная модель ...)` | не запущен llama-server; запустите блок «Локальная модель» или укажите `--local-url` |
| `RAG: не использован (индекс RAG пуст)` | выполните `--build-index` при запущенной Ollama |
| ревью обрывается на середине | увеличьте `--max-tokens` |
| в workflow нет комментария | не заданы секреты или нет прав `pull-requests: write` |
